Dockerfile Instructions

Layers · Build Context
FROMBase image (alpine, ubuntu, scratch)
WORKDIRSet working directory for next instrs
COPY / ADDCopy files; ADD also unpacks tar/URLs
RUNExecutes at build time, creates a layer
CMDDefault runtime command (overridable)
ENTRYPOINTFixed executable, CMD becomes its args
ENV / ARGENV persists in image; ARG build-time only
EXPOSEDocuments port (doesn't publish it)
VOLUMEDeclares mount point for data
USERRun as non-root user (security)
HEALTHCHECKCommand to test container health
.dockerignoreExcludes files from build context
Multi-stage builds: use multiple FROM stages, COPY --from=build to shrink final image size.
🏗️

Multi-Stage Dockerfile Example

Build → Runtime
FROM node:20 AS build WORKDIR /app COPY package*.json ./ RUN npm ci COPY . . RUN npm run build FROM nginx:alpine COPY --from=build /app/dist /usr/share/nginx/html EXPOSE 80 HEALTHCHECK CMD curl -f http://localhost/ || exit 1 CMD ["nginx", "-g", "daemon off;"]
Final image only contains nginx + built assets — not Node.js or source, keeping the image small and secure.

Best Practices & Security

Image Hygiene
Use slim/alpine baseSmaller attack surface, faster pulls
Non-root USERAvoid running as root in container
Pin versionsnginx:1.27-alpine, not nginx:latest
.dockerignoreExclude .git, node_modules, secrets
Multi-stage buildsKeep build tools out of final image
No secrets in imageUse build secrets / env at runtime

🏛️

Cluster Architecture

Control Plane · Nodes
Control Plane
kube-apiserverFront door — all requests go through it
etcdKey-value store — cluster's source of truth
kube-schedulerAssigns pods to nodes
controller-managerRuns reconciliation loops (deployment, node, etc.)
cloud-controller-managerCloud-specific integrations (LB, volumes)
Node Components
kubeletAgent ensuring containers run in a Pod
kube-proxyMaintains network rules for Services
Container runtimecontainerd / CRI-O runs containers
Desired state (in etcd) is continuously reconciled with actual state by controllers — this is the core control loop pattern.

Probes & Resources

Health · Requests/Limits
Probes
livenessProbeRestarts container if it fails
readinessProbeRemoves pod from Service if it fails
startupProbeDelays other probes for slow-starting apps
TypeshttpGet, tcpSocket, exec
Resources
requestsGuaranteed — used for scheduling
limitsMax allowed — CPU throttled, memory OOMKilled
QoS: Guaranteedrequests == limits for all resources
QoS: Burstablerequests < limits
QoS: BestEffortno requests/limits set

HCL Core Blocks

Syntax Reference
terraform { required_version = ">= 1.5" required_providers { aws = { source = "hashicorp/aws", version = "~> 5.0" } } backend "s3" { bucket = "tf-state", key = "prod/terraform.tfstate" region = "us-east-1", dynamodb_table = "tf-lock" } } provider "aws" { region = "us-east-1" } resource "aws_instance" "web" { ami = var.ami_id instance_type = "t3.micro" } variable "ami_id" { type = string } output "ip" { value = aws_instance.web.public_ip } locals { name_prefix = "prod-app" }
Reference: resource → type.name.attr | var → var.name | local → local.name | module → module.name.output

Common Gotchas

Cross-Tool Pitfalls
DockerForgetting EXPOSE ≠ publishing (-p) a port
Docker:latest tag causes non-reproducible builds
KubernetesNo resource limits → node pressure / OOMKills
KubernetesSecrets are base64, not encrypted, by default
TerraformNever commit terraform.tfstate to Git
Terraformfor_each preferred over count for stable resource identity
