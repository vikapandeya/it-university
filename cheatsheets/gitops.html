Continuous Delivery Through Git — Principles, Tools & Production Patterns

ArgoCD Flux Git Print-Ready
Push vs Pull
Classic CI/CD pushes to the cluster; GitOps agents pull from Git and reconcile — no cluster credentials leave the cluster
Source of Truth
Git is the single source of truth — the cluster's live state should always be derivable from a commit
Drift
Any manual kubectl edit is "drift" — GitOps agents detect and can auto-revert it
Rollback
Rolling back = git revert, not a special tool command — the agent reconciles to the reverted state automatically

GitOps Principles

1️⃣

The 4 GitOps Principles

DeclarativeEntire system state described declaratively (YAML/Helm/Kustomize)
Versioned & ImmutableDesired state stored in Git — full history, diff, and audit trail for free
Pulled AutomaticallySoftware agents pull the desired state — no external system pushes into the cluster
Continuously ReconciledAgents constantly compare actual vs. desired state and converge toward it
This is the CNCF/OpenGitOps definition — any tool that satisfies all four is "doing GitOps," not just ArgoCD/Flux specifically.
🔀

Push CD vs GitOps (Pull CD)

DimensionPush CD (Jenkins/GH Actions → cluster)GitOps (Pull)
CredentialsCI system holds cluster admin credsOnly the in-cluster agent has cluster access
Drift detectionNone — pipeline just runs onceContinuous — agent reconciles forever
Audit trailCI job logs (often ephemeral)Git history (permanent, reviewable)
RollbackRe-run an old pipeline jobgit revert, agent auto-applies it
Multi-clusterPipeline must know every targetEach cluster's agent pulls its own config

ArgoCD

📄

Application CRD

apiVersion: argoproj.io/v1alpha1 kind: Application metadata: name: myapp namespace: argocd spec: project: myproject source: repoURL: https://github.com/org/gitops-repo.git targetRevision: main path: apps/myapp/overlays/production destination: server: https://kubernetes.default.svc namespace: production syncPolicy: automated: prune: true # delete resources removed from Git selfHeal: true # revert manual cluster changes syncOptions: - CreateNamespace=true
prune: true + selfHeal: true together give you full declarative enforcement — Git is the only way to change anything.

App-of-Apps Pattern

A single "root" ArgoCD Application whose source is a folder of other Application manifests — lets you manage 50 microservice deployments by syncing one parent app.

Typical Repo Layout
gitops-repo/ root-app.yaml ← points ArgoCD at apps/ apps/ service-a.yaml ← Application CRD service-b.yaml ← Application CRD service-c.yaml ← Application CRD
ApplicationSet generalizes this further — generate Applications dynamically from a cluster list, Git directories, or a pull-request generator.
🗂️

Environment Promotion Patterns

Branch-per-envmain → staging → production branches; promote via merge/PR
Folder-per-envOne branch, overlays/dev / overlays/prod via Kustomize
Repo-per-envSeparate repos per environment — strongest isolation, more overhead
Folder-per-env (Kustomize overlays) is the most common pattern — one source of truth, explicit per-env diffs, easy to review in a single PR.

Secrets & Progressive Delivery

🔑

Secrets Management in GitOps

You Can't Commit Plaintext Secrets
Sealed SecretsBitnami controller — encrypt client-side, only the cluster's private key can decrypt
SOPSEncrypt specific YAML/JSON values with KMS/PGP/age; decrypted at apply time
External Secrets OperatorSyncs secrets FROM Vault/AWS Secrets Manager/etc INTO the cluster — Git never stores secret values at all
External Secrets Operator is the strongest option — the secret value itself never touches Git, even encrypted.

Troubleshooting & Interview Prep

🔍

Common Sync Failures

OutOfSync foreverA field is mutated by an admission webhook/defaulting after apply — add it to ignoreDifferences
Sync stuck "Progressing"A resource's health check never passes — check Deployment readiness probes
PruneLast / orphaned resourcesA resource was removed from Git but prune: false — it's never deleted from the cluster
selfHeal fighting an operatorAnother controller (HPA, cert-manager) modifies a field GitOps also manages — scope ownership clearly or ignore that field
💬

Common Interview Questions

Q"What's the difference between CI and GitOps/CD?" — CI builds/tests and produces an artifact; GitOps is how that artifact's deployment is declared and reconciled via Git, decoupled from the CI pipeline.
Q"How do you handle secrets in a GitOps repo?" — never commit plaintext; use Sealed Secrets, SOPS, or (preferably) External Secrets Operator pulling from a vault.
Q"How does ArgoCD detect drift?" — it continuously diffs the live cluster state against the Git-declared manifests and marks the Application OutOfSync when they differ.
